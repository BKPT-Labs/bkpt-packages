BKPT candidate architecture policy, version6; independent review required before publication. It extends version2, which stays in force for every profile it names, and replaces version5: every rule of version5 stands word for word on the same line, and rules are added after them: the I2C signal functions, instances and pin domain with a board rule for one header pad, kernel clock citations, analog reading, input capture, the update interrupt on channel timers, GPIO input, a checksum unit, the independent watchdog and what the earlier texts are.
Scope: one STM32C5 part and package at a time, as its target states, with HAL2 pack2.1.0 and the captured c5-hal2-minimal foundation. Board population, solder-bridge state, silicon revision and electrical setup remain unverified.
Inventory: pins, signal routes and interrupts transcribed from the pinout descriptor, device header and startup vector table record declared presence and routing. A route is not a capability, an electrical permission, a statement about board wiring or proof that two signals can be used together.
Debug access: the pads on board nets DBG.SWDIO and DBG.SWCLK carry the debug connection. They are occupied by the base and no capability may adopt them.
Clock input: the captured clock configuration runs from the external oscillator, so the pads on board nets OSC_IN and OSC_OUT are occupied by the base and no capability may adopt them.
General allocation: a configurable pad is eligible for general allocation only when its board net joins the device pad to connectors and solder bridges alone and no explicit exclusion names it. A pad whose net also carries another component, a debug or trace signal, an oscillator or a USB line stays outside general allocation until that circuit is reviewed. Eligibility is a conservative BKPT allocation rule, not an electrical qualification; solder-bridge state decides whether a connector actually reaches the pad.
Boot strap: the pad on board net PH2_BOOT0 selects the boot mode at reset and stays outside general allocation.
Console: the pads on board nets PA2 and PA3 are the routes the reviewed UART profiles use for the board console. They stay outside general allocation, and only a UART profile may take them.
GPIO output domain: any pad eligible for general allocation may be configured as a push-pull output through the reviewed GPIO output card. The application initializes the selected pad. Level, load, polarity and timing remain application obligations.
GPIO interrupt domain: any pad eligible for general allocation may be configured as an input with a CPU interrupt through the reviewed GPIO interrupt component. External line n serves pad index n of every port, so one line is one exclusive resource regardless of port. Interrupt priority5 is an authored integration choice, not a silicon limit.
SPI pin domain: the SCK, MISO and MOSI signals of a covered SPI instance may use any descriptor route to a pad eligible for general allocation; the alternate function comes from the selected route. The rates, mode and DMA rules of version2 are unchanged. Signal integrity at the selected rate on a given pad and connector is not verified.
Signal functions: a managed profile names a signal by the role it plays, so that one profile can serve several instances. The role is read from the manufacturer's peripherals descriptor, which types each signal of an instance within a protocol; no tool derives it from a signal name. In the SPI protocol CLK is spi_sck, MISO is spi_miso and MOSI is spi_mosi. In the Serial protocol TX is uart_tx and RX is uart_rx. A function states which role of the profile a signal plays and nothing about timing or electrical behaviour.
SPI instances: the managed SPI transfer profile covers every instance the peripherals descriptor declares with type spi, IP c7amba_spi2s3 and version2.3, unless the part's limitations remove it or the package bonds none of its signals. An instance takes its kernel clock from the bus the descriptor places it on, and under the captured clock configuration PCLK1 and PCLK2 are both 144MHz, so the rate choices of version2 apply to each. SPI1 stays the first choice. I2S operation, the NSS and RDY signals and other kernel clock sources are not covered. The fixed SPI1 handle profile of version2 is unchanged.
UART instances: the managed UART transfer profile covers every instance the peripherals descriptor declares with type usart or uart, IP c7amba_sci3 and version3.4, unless the part's limitations remove it or the package bonds none of its signals, in asynchronous 8N1 mode with a handle private to the generated unit. The same IP declared with type lpuart is a different class and is not covered. An instance takes its kernel clock from the bus the descriptor places it on, 144MHz under the captured clock configuration, and the SDK derives the divider from that clock at configuration time. USART2 stays the first choice. Synchronous clock output, hardware flow control and the fixed USART2 handle profiles of version2 are outside this rule.
UART pin domain: the transmit and receive signals of a covered UART instance may use any descriptor route to a console pad or to a pad eligible for general allocation; the alternate function comes from the selected route. Both pads are push-pull alternate outputs without pull, as in the captured USART2 configuration, so an unconnected receive pad floats. Signal integrity at the selected rate is not verified.
DMA request lines: a request line of a covered instance is recorded only when the peripherals descriptor names the request, the reference manual request table gives that name a selector, and the SDK low-layer definition for each controller and the SDK enumerator agree on it. Every channel of both controllers can take any request, and one request may drive one active channel at a time, as version2 states for the lines it names.
User button: the pad on board net PC13 shares that net with push-button B1 and resistor R13, and the netlist places the other side of B1 on net 3V3 and the other side of R13 on net GND. Read as a button to the supply with a pull-down, a press reads high; that reading comes from net membership alone and is not checked against the schematic drawing or the populated board. The pad stays outside general allocation and may be allocated only as an interrupt input, because an output driven low would oppose the supply through a pressed button.
Timer channels: the timer channel allocation covers every instance the peripherals descriptor declares with type tim, IP c7amba_gptimer2 and version5.0 that has channel signals, and its non-inverted channel signals with identifiers CH1 to CH4. It allocates a timer and one routed pad and generates no code. The SDK channel symbol of a signal is the one the SDK describes as the timer channel of the number in the descriptor's signal identifier; that pairing does not state that every mode of a channel exists on every timer. One counter serves every channel of a timer, so an allocation takes the whole timer and two allocations never share one. Period, duty, polarity, compare or capture use, complementary outputs, dead time and break inputs are application decisions, and no timing is claimed.
Analog inputs: the analog input allocation covers every instance the peripherals descriptor declares with type adc, IP c7amba_aditf6 and version3.0, and its external input signals. It allocates one routed pad for analog use and generates no code. The SDK channel symbol of an input is the one the SDK describes as the channel to the pin signal of the number in the descriptor's signal identifier. The pads PC4, PC5, PB0 and PB1 reach inputs IN2, IN5, IN6 and IN7 only after the SBS pin remap, which this rule does not set, so they are outside it and every covered input has exactly one pad. The converter is one shared unit: each offered input may be allocated once, and all of them at the same time. Sequencing, sampling time, calibration, reference voltage, source impedance and accuracy are application decisions and are not claimed. Internal channels, injected conversions and differential inputs are outside this rule.
Backup domain pads: PC13, PC14 and PC15 are outside general allocation on every board. The datasheet states that their function depends on RTC registers a system reset does not clear, and the captured startup does not establish that state; it also notes that toggling PC13 can disturb a crystal on PC14 and PC15. A board may still name one of them for a use it documents, such as a push-button input, and that use carries the same caveat.
Supersession: the minimal-foundation policy version1 and the GPIO interrupt scope text were written for STM32C542RCT6 in LQFP64 on the NUCLEO-C542RC and admit only pads PA4 and PA5 for GPIO. Their ownership, capacity and lifecycle statements stay in force wherever this policy is applied. Their limits to that part, package and board and to those pads are replaced by the domain rules of this policy. That replacement is an authored extension and needs the same independent review as the rest of this policy.
Foundation pads: the captured foundation uses the debug signals DEBUG_SWDIO and DEBUG_SWCLK and the oscillator signals RCC_OSC_IN and RCC_OSC_OUT. Every pad a package routes those signals to must be reserved by the board that is applied, and a board that does not reserve them is refused. A board can add restrictions and cannot omit these.
PWM output: the PWM output component covers the same instances and channel signals as the timer channel allocation and, like it, takes the whole timer and one routed pad. It generates one edge-aligned output in PWM mode1, active high, counting up from the internal clock, with compare preload so that a duty change takes effect at a period boundary; of several changes within one period the last one applies, and the first period after a start can be shorter at the pad. The frequency choices are the exact divisions of the captured 144MHz timer clock listed in the PWM rate table, each with a prescaler of at most 65534 and a period register between 999 and 65534, so that full duty fits a 16-bit compare register and one thousandth of the period is at least one count. Duty is set at run time in thousandths of the period and rounded down to a whole count. On a timer with a break function the SDK enables the main output when the channel starts; break inputs, dead time, complementary outputs and every other channel of the timer are not used. The level of the pad while the output is stopped is not established. The frequencies are arithmetic on the nominal clock, not measured timing, and the electrical load and edge quality on a given pad are not verified.
Two-wire signal functions: the managed I2C profiles name the clock and data signals of an instance by the role each plays, read from the I2C protocol entry of the manufacturer's peripherals descriptor in the way the signal functions rule reads the others. In the I2C protocol SCL is i2c_scl and SDA is i2c_sda. The SMBus alert signal has no role here and is not used.
I2C instances: the I2C controller profiles cover every instance the peripherals descriptor declares with type i2c, IP c7amba_i2c2 and version2.1, unless the part's limitations remove it or the package bonds none of its signals. An instance takes its kernel clock from the bus the descriptor places it on, and the fixed timing value of version2 is stated only for the captured 144MHz of that clock. The fixed 1MHz timing, 7-bit addressing, DMA and controller-only rules of version2 are unchanged. Target mode, SMBus, 10-bit addressing and other bus rates are not covered.
I2C pin domain: the SCL and SDA signals of a covered I2C instance may use any descriptor route to a pad that is eligible for general allocation or that the board names for this use, provided the pinout descriptor gives that pad the I/O structure option f, which the descriptor describes as an I2C Fm+ capable I/O. The alternate function comes from the selected route, and the pads the profiles were reviewed with stay the first choice. The option is a declared structure: pull-ups, bus capacitance, rise and fall times and the drive strength itself are not verified on any pad.
Two-wire header: the pad on board net PB9 shares that net with capacitor C13 and resistor R33 besides solder bridges, so it stays outside general allocation. The I2C controller profiles of version2 were reviewed with it as a data pad, and only an I2C profile may take it. What C13 and R33 do to a bus on that net is not established.
Kernel clocks: for an instance of a covered class the manufacturer's clock descriptor is cited for every clock element that names the instance: the sources a selector offers, a divider, and the highest frequency the descriptor allows where it states one. The descriptor describes what can be configured, not what the captured configuration selects. The selected source and its frequency are stated by the rule of each capability and checked by its unit at run time where the SDK reports them.
Analog reading: the analog reading component covers the same converter instances, inputs and pads as the analog input allocation and shares the converter in the same way: each offered input may be read by one unit, and as there the pads PC4, PC5, PB0 and PB1 are outside it. The first unit on a converter brings it up with the ADC and DAC kernel clock taken from HCLK and divided by 8, which is 18MHz under the captured 144MHz configuration and lies inside the 8 to 36MHz the datasheet gives for the ADC clock at a supply of 2.7 to 3.6V; it sets 12-bit resolution, software trigger and one conversion per request, activates the converter and runs its offset calibration. Every unit on a converter uses that one handle. A read converts its input once with the longest sampling time, 288.5 clock cycles, and returns the 12-bit count: the pad voltage as a fraction of the reference voltage VREF+. The reference is not measured and no conversion to volts is offered. The SDK configures a channel only while the converter is stopped, so a read of another input than the last one stops, switches, starts and calibrates the converter first. That kernel clock also feeds the DAC, and the component sets it for both. Reads belong to one thread. Accuracy, source impedance, noise, the internal channels, injected and differential conversion, triggers, interrupts and DMA are outside this rule, and a build is not a measurement.
Input capture: the input capture component covers the same timers, channel signals and pads as the timer channel allocation and, like it, takes the whole timer and one routed pad. The timer counts microseconds, the captured 144MHz timer clock divided by 144, over a 16-bit period, and the channel captures both edges of its own pin. The capture unit and the input source of a signal are the SDK symbols of the channel number in the descriptor's signal identifier, the input source being the one the SDK describes as connected to that channel signal. A measurement is polled: it waits for a rising edge, the falling edge after it and the next rising edge and returns the period and the high time in microseconds, or stops at a time limit the caller sets. An edge that arrives before the previous one was read is reported as an error, through the timer's overcapture flag or a capture found already waiting, never as a value; the shortest measurable distance between edges depends on the polling loop and on interrupts and is not stated. The pad is an input with the pull the request selects. Input filtering, prescaled capture, capture by interrupt or DMA, the other channels and the XOR input are not used. Times are counts of the nominal clock, not measured against a reference.
Channel timer update interrupt: the periodic update interrupt component of version2 may also run on a timer the timer channel allocation covers. The update interrupt of such a timer is the one the peripherals descriptor connects to its UPD interrupt signal or, on a timer with a single vector, to its GLOBAL signal, and the device description must declare that interrupt inside the timer. The component, its exact rate choices at the captured 144MHz timer clock and its rules are those of version2, unchanged; it takes the whole timer and uses no channel. A timer with a single vector raises every timer event on it, and the component enables only the update event. TIM6 and TIM7 stay under the version2 capability.
GPIO input domain: any pad eligible for general allocation may be allocated as a digital input the application reads through the SDK. No code is generated: the application enables the port clock, initializes the pad as an input with the pull it needs and reads the pin state. Input thresholds, hysteresis, debouncing and the external circuit are application matters, and an input without a pull that nothing drives reads an undefined level.
Checksum unit: the CRC-32 component covers every instance the peripherals descriptor declares with type crc, IP c7amba_integtest1 and version2.4; the unit uses no pad, so it exists on every package of the die. It computes, over a buffer of bytes in one call, the 32-bit CRC with polynomial 0x04C11DB7 and initial value 0xFFFFFFFF, every input byte and the result bit-reversed and the result inverted: the CRC-32 of ISO 3309 and zlib, whose value for the nine ASCII characters 123456789 is 0xCBF43926. The inversion is done by the unit and the rest by the peripheral as the SDK configures it. One computation at a time, from one thread; other polynomials and sizes and accumulation across calls are not offered. The check value is arithmetic, stated so that a program can be tested against it, not a measurement.
Independent watchdog: the watchdog component covers every instance the peripherals descriptor declares with type iwdg, IP c7amba_wdgls and version4.2; the unit uses no pad. Once started the watchdog cannot be stopped or reconfigured before a reset, so the generated initialization only prepares the handle and the application starts it when it is ready to refresh it. The reset time is one of the listed choices in milliseconds, which the SDK converts to a prescaler and a reload value for the nominal 32kHz of the low-speed internal oscillator; no window and no early interrupt are set, and the unit reports the time the SDK set. The oscillator frequency is not measured, so the real time differs with it. Whether the counter runs while a debugger halts the core or in the low-power modes, and what the option bytes add, are not covered, and a build does not exercise the reset.
Earlier texts: where this policy says version2 it means the reviewed texts the graph pins: the minimal-foundation policy version1 for ownership, capacity and lifecycle, and the transfer rate policy for the SPI rates and UART baud rates that are offered. Two sentences of the minimal-foundation policy, that every selected serial capability references the one USART2 initialization card and that basic_stdio output needs only a selected serial capability, hold for the fixed USART2 profiles alone: the managed UART transfer profile initializes a handle of its own, as the UART instances rule states, and that handle is not the one basic_stdio uses.
All capability domains remain open/incomplete. Resource allocation, materialization, compilation and hardware observation are distinct; no complete errata/electrical/application qualification is claimed.
